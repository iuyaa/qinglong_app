# 登录与多面板稳定性 003

目标版本：3.0.3。用户已反馈 3.0.2 真机安装后，任务、脚本和日志页面目视正常；该反馈不代表所有写操作通过。

## 修复

- 登录请求使用独立 HTTP 客户端，目标地址、Token、登录方式在完整登录成功后才替换。错误密码、取消两步验证、页面退出和被后续登录取代的请求不会更换原会话；空 Token 不能当成成功。
- 二次验证共用一个流程，要求六位数字；验证码错误可重试，取消返回原页面。账号密码错误的 401 不再额外尝试旧登录接口，旧接口仅在 404 时尝试。
- 账号密码与应用密钥登录过期都返回登录页，保留原登录方式。识别青龙将权限不足也返回 401 的行为：`暂无权限` / `Access denied` 映射为权限提示，不清除有效会话。兼容 HTTP 401 与 HTTP 200/body code 401。
- 登录成功、退出和请求客户端替换时关闭旧连接；API 实例和页面路由绑定原 HTTP 客户端，页面退出动画期间的轮询也使用原会话。旧日志响应和旧 401 不会更新新会话，也不会把旧任务操作发送到新面板。不自动重放业务请求。
- 成功切换后清理该槽位的任务、配置、依赖等 Provider 缓存，重建首页并清除旧页面栈。已销毁模型忽略迟到的刷新通知。
- 多面板按准确槽位保存，补齐中间空槽位；读取时保留空位，避免先登录后面的槽位后重启错位。普通退出保留应用密钥登录方式。

## 验证

新增 `test/session_test.dart`，使用两台合成回环 HTTP 服务和生产会话/Provider 状态，覆盖错误密码、空 Token、2FA 取消/错误/重试、新登录取代旧登录、旧日志迟到、旧任务请求阻断、缓存清理、缺少权限、过期重登、不重放 POST、独立槽位及存储恢复。保留原有四项测试。

命令：`flutter test`；[Actions 第 7 次运行](https://github.com/iuyaa/qinglong_app/actions/runs/34095658457)测试步骤通过，共 5 个测试。完整构建与成品校验见 [BUILD-003.md](BUILD-003.md)。

本轮没有连接真实面板修改登录配置、创建应用、操作现有任务或脚本。真实 Client ID/Secret 授权、真实 TOTP、3.0.3 Android 真机交互、账号排序与全部继承功能：NOT_RUN。测试中的地址、凭据和 Token 都是合成数据。
